# Privacy policy draft and dashboard worksheet

Publisher identity, public policy and GitHub Issues contact have been supplied. The authoritative public-page source is `docs/public/privacy.md`, revised 2026-10-17 with an explicit Limited Use commitment. This worksheet remains a code-to-dashboard recommendation, not checked certifications or Chrome Store approval. Other release blockers remain separate.

Purpose: user-requested subtitle display, transcription and translation on YouTube. CueFlora source has no publisher analytics/advertising endpoint. That does not mean no user data is processed.

Data and recipients:

- Video ID, title, description and caption-track information are read from the current YouTube page. Captions/media are requested from YouTube/its delivery servers, which receive network metadata such as IP address. The frozen downloader does not read unrelated yt-dlp configuration/plugins or import browser cookies.
- Pressing Run with AI transcription downloads temporary audio to the local helper, prepares it and uploads chunks with language/model instructions to the user-selected transcription service.
- AI translation sends subtitle text, source/target languages, preceding/following cue context and video title/bounded description to the user-selected translation service. This can contain speech-related personal information.
- Explicit model discovery sends a metadata request and an API key if configured to the selected service. It does not perform inference.
- Preferences, provider endpoints/models, encrypted API keys and subtitle caches are stored locally in extension storage. Remembered keys use user-scoped Windows DPAPI, bound to stage/service address; plaintext exists temporarily for entry and authenticated requests inside the helper. Settings never receive existing plaintext keys. Active Run session records retain opaque references, not key payloads. DPAPI does not defend against malware running as the same user. Store candidates require remote HTTPS; exact loopback HTTP remains allowed. Preview remote HTTP requires acknowledgement and can expose data/credentials in transit.
- Local optional evidence capture, explicitly enabled through `CUEFLORA_EVIDENCE_DIR`, retains audio/uploads/raw results/subtitles and stage mappings in append-only private files. Plaintext/encrypted credential payloads and signed-media URL queries are excluded/redacted. Normal diagnostics use counts/timings/IDs/reasons. Capture is off by default and is not uploaded by CueFlora.

Retention/control: caches are locally bounded (20 records/8 MiB); preferences/keys remain until edited or extension data is removed. Temporary audio is managed by the Run's temporary directory; capture files intentionally survive and must be removed separately by their owner. Helper uninstall quarantines runtime versions and preserves settings/evidence. Selected providers control their own retention, pricing and terms; users must review them. No source assertion guarantees filesystem backup erasure or third-party deletion.

0.1.3 additionally refuses page-script synthetic Run clicks and downloaded files outside the current processing directory. Public frozen helpers enforce their own HTTPS policy even if a client asks for preview behavior. These safeguards do not remove download/challenge-execution policy gates. The prepared public-page version is `docs/public/privacy.md`; supply the same real publisher/contact/effective-date information to both before publication.

Migration: opening settings protects and verifies legacy CueFlora keys before removing their plaintext record. Failure preserves the original with an incomplete-migration warning; successful encrypted persistence and failed legacy cleanup are reported separately. Explicit retry is available. Previously retained private evidence is not rewritten. Keep/Replace/Remove and address-reuse confirmation control saved keys; already bound Runs retain their original key reference until release. No claim of erasing backups or protection from same-user malware is made.

Dashboard worksheet (draft, validate against final code and current form): website content (audio/captions/video metadata), web history/current visited video identifiers as applicable, user activity required for the feature and authentication information (API keys) may be relevant. Do not answer "no data" simply because storage is local or recipients are chosen by users. Explain use solely for the single subtitle purpose, recipients and limited-use commitments only once the publisher can make them truthfully. No sale, advertising or creditworthiness use exists in the audited source. Review the actual form categories and final legal commitments before certification.
