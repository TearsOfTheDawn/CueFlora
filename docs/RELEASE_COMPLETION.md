# CueFlora 0.1.9 release preparation

This source prepares Windows x64 / Chrome candidates. It does not publish, install into the live environment, provision AI services or certify semantic subtitle accuracy. Substrata and previous packages remain separate.

The audited source is public at `TearsOfTheDawn/CueFlora` under the publisher's explicit source/pages authorization. Prelaunch privacy/help pages are live: deployment success and all six exact HTTPS response hashes were verified on 2026-10-15. Source and help publication is not a software launch. The chosen launch route is a public Store listing once the remaining gates are resolved, not a mandatory private test release. The original source import and packaged candidates remain preserved. Remote regression checks complement local engineering evidence; neither establishes clean-machine/browser acceptance or distribution clearance.

It retains 0.1.7's corrected LICENCE/UNLICENSE discovery. Exact offline Cargo replay preserves 1672 original files, 13 more than 0.1.6, and reduces missing package-root notices from 125 to 122. The separate fixed-commit repository catalog remains 68 recovered packages/77 notice files and 52 historical unresolved lookup rows; these are not a combined shipment/coverage count. Neither notice recovery nor notice-only inputs establish corresponding-source compliance or redistribution approval. Earlier packages remain immutable. App version fields in package.json, both npm root records, native pyproject and the native editable-project lock must agree; the metadata regression test checks these actual files. Obtain exact input caches using `packaging/bootstrap_public_cache.py --online`, then restore the pinned Python environment using `packaging/bootstrap_offline.py --official`. The command restores official Node 24.19.0/npm 11.17.0 and validates the archive/executable and all 1921 npm files; no installed/global npm module dependency is needed. Run preparation with the restored interpreter:

```text
python packaging/prepare_windows.py --output artifacts/fresh-candidate --cache artifacts/inputs --evidence-cache artifacts/evidence --audio-cache artifacts/audio-inputs
```

The command restores the portable compiler, builds FFmpeg/ffprobe 9.0.2 and Opus 1.6.1, rebuilds the same yt-dlp 2026.08.19 source on pinned Python 3.13.15, runs public synthetic conformance checks, tests/builds both extensions, and builds two runtime/Setup pairs. Inputs never fall back to latest. No media or inference is requested during its metadata/extractor checks.

Use `--online` for initial preparation if the exact npm/source/tool caches are not yet complete; omit it for offline repetition with a fresh output. Preparation restores its own pinned Node/npm. The final source archive is also unpacked into an independent checkout and all suites/browser builds rerun with private import/capture/tool overrides removed; its archive hash must match the candidate. Delivery includes a package-specific `START_HERE.md` naming the actual matching unpacked profile and refusing to treat the keyless submission ZIP as a preview. ## Approval without rebuilding

Candidate construction is separate from publication. `external-approvals.json` starts with every gate pending. Reports must contain the same source, runtime inventory, installer and Store ZIP hashes, gate/status, reviewer and reason; their actual contents are hash-checked. Only clean-Windows and real-Chrome acceptance may be explicitly waived by the publisher. Licensing, policy/security, genuine screenshots, real public locations, Store approval and publication authorization cannot be waived or inferred from tests. Recorded declarations are not authenticated legal/store decisions.

`licence-assessment.template.json` is pending, not an approval. Where the ledger identifies review-required native/Deno ambiguity, a later actual licence reviewer must supply an assessment bound to that exact ledger and candidate, address every issue, and reference actual candidate-relative notice/source/recipe/terms/scope files by hash. Non-shipment judgments require scope evidence. Mandatory missing source/notices and unassigned files cannot be cleared by this review path; they must be fixed. The tooling verifies recorded claims and unchanged evidence bytes, not the reviewer's identity or legal expertise. A mere `passed` flag without the complete assessment does not clear incomplete dependency evidence.

The pending template is also copied into `release-assets` and covered by its inventory. In the dependency ledger, each file's component `ledgerRow` refers to a zero-based entry in `rows`, which retains the complete original notice/source evidence. These references avoid repeating entire notice lists for every file; no original evidence is removed, and unmatched files or mismatched hashes still fail or remain blockers.

The installer payload does not embed mutable approval records. Freeze candidate bytes before review. Keep exact verified sources, notices and build instructions together with binaries; promote the same reviewed artifacts, not a rebuilt substitute.

`release-assets` contains immutable versioned filenames plus checksums/inventories. `promote_release.py` validates every required external decision and unchanged candidate bytes before producing a dry-run promotion command. Execution additionally requires `--execute --confirm-version <exact-version>` and publisher-controlled GitHub CLI authentication; it verifies existing remote review assets and promotes a prerelease only. It does not create a repository, release, tag, replacement upload or Store publication. No such execution is authorized or performed during implementation.

## Minimum publisher steps

1. Publisher/repository, GitHub Issues support, the Store draft ID/public key and prelaunch privacy/help locations are established. Build and freeze the exact Store-bound candidate using those supplied values. No account passwords or private signing keys are needed for construction.
2. The publisher chose to defer clean-Windows/real-Chrome Run testing until after public launch. Record that decision against the final candidate as an explicit untested waiver, never a successful test. Do not require private Store publication first. Genuine CueFlora screenshots remain required for the Store listing.
3. Resolve outstanding redistribution and security/download-policy reviews, make the matching helper genuinely downloadable, and update the existing Store draft with the higher-version ZIP and accurate listing/privacy/reviewer materials. Select Public visibility. Submit with automatic publication disabled while coordinating the final launch. Reviewer instructions disclose helper installation, temporary audio download, native challenge execution, configured service prerequisites and data transfers. Any requested reviewer-only credentials stay out of public source/artifacts.
4. After actual Store approval and all non-waivable gates, launch the matching GitHub release and Store item under the publisher's public-release direction. Until then do not infer licence/security/Store approval from that direction. If review objects to the architecture, obtain a separate approved remedy rather than disguising the behavior. The publisher can then test the ordinary new-user installation path as chosen.

GitHub Releases holds Setup/source bundles, GitHub Pages holds privacy/install pages, and GitHub Issues provides support. The first installer is unsigned; do not disable antivirus. No signing, ownership, licence approval, real-browser result, genuine screenshot, Store approval or public URL is invented by the preparation command. Firefox/other-platform packaging and AI provisioning remain outside this release.
