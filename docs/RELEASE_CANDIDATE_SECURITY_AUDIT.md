# CueFlora release-candidate security audit

Original production-boundary audit: 2026-10-13. Public candidate-mode wording refreshed 2026-10-14; the core subtitle/credential pipeline remains unchanged. This is an engineering audit, not independent security clearance, browser acceptance or a safety guarantee. No live installation, browser automation, video download or inference was performed for the audit.

| Boundary | Evidence and narrowly scoped changes | Remaining limitation |
|---|---|---|
| Explicit Run | Player Run now rejects untrusted DOM events through `utils/userRun.ts`; synthetic page clicks cannot start the workflow. Keyboard/mouse browser input remains supported. | Automated tests are not live browser acceptance. The page still controls its DOM; this is not authentication of caption data. |
| Credentials | `credentials.py`, background provider ownership and credential tests retain user-scoped noninteractive DPAPI, stage/address binding, opaque Run references and verified migration before plaintext removal. | Same-user malware can read memory/use DPAPI. Failed legacy migration intentionally preserves the original key with a warning. |
| Transport | Public frozen runtimes use their packaged HTTPS policy, not a client-supplied downgrade. Provider redirects remain rejected. Preview remote HTTP remains acknowledged compatibility behavior. | Acknowledged remote HTTP is not secure transport or public-profile clearance. No provider compatibility/inference was tested. |
| Native messages | Exact reads, 8 MiB input/1 MiB output limits; background shape, sender-role, job, revision and response validation; settings-only credential operations. | Native stdin is not an authentication channel against same-user processes. Signing/publisher authenticity is separate. |
| Temporary audio | Each Run owns a `TemporaryDirectory`; downloader output must now be a nonempty ordinary file within that root. Missing/empty/outside-root output fails without exposing a filesystem path. | Normal cleanup is not secure erasure; process termination/backups can retain bytes. Explicit evidence capture intentionally survives. |
| Downloader | Frozen resolution selects pinned bundled tools, ignores user configuration/plugins and disables remote component downloads. Arguments are passed as a list, not a shell command. | YouTube challenge input still executes in native Deno. Download authorization and native challenge/store eligibility remain unresolved. No architecture change was approved. |
| Evidence/diagnostics | Allowlisted metrics/reason codes and secret exclusion; plaintext/ciphertext payloads are not exported to player diagnostics/captures. Source export excludes private captures, environments and generated outputs. | Optional audio/text evidence is sensitive. Pattern-based source scanning is not exhaustive secret detection. |
| Setup/build | Exact source/runtime binding, compiler-input audit, payload hash inventories, conflict rejection, OS locking, recovery journals and temporary-root lifecycle tests. Schema 2 public candidate construction requires actual identity/binding and HTTPS, not invented approval. Hash-bound external decisions separately gate public promotion. | Hashes do not authenticate a publisher or establish legal clearance. Same-user tampering and unsigned Windows warnings remain limitations. |

Automated results, actual Windows DPAPI probes, missing-library cases, clean-source checks and installer lifecycle evidence are recorded in the delivered candidate's `readiness.json` and handoff. External clean-Windows/Chrome acceptance remains explicitly separate.

## Policy conclusion

Current [Chrome Store policies](https://developer.chrome.com/docs/webstore/program-policies/policies) and [MV3 requirements](https://developer.chrome.com/docs/webstore/program-policies/mv3-requirements) were reconsidered on the audit date. A native helper does not establish an exception to download authorization, secure handling or remote-code review. Submission must honestly describe temporary audio downloading and challenge execution. No claim of eligibility/approval is made. If a reviewer requires different ingestion or execution behavior, seek a separately approved architecture plan; do not disguise the behavior or treat a disclaimer as a remedy.
